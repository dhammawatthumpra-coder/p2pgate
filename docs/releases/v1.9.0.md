# p2pgate v1.9.0

Hardening release: catch configuration mistakes before they cause outages, and
tighten the SOCKS5 policy per client.

## New commands

```sh
p2pgate config validate [--json] [--config <path>]
p2pgate config show     [--json] [--config <path>]
```

`validate` runs the daemon's normaliser and prints a summary; it exits `1` when
the file is missing or invalid, and `--json` reports
`{ ok: false, error, message }`.

`show` prints what the daemon actually sees, with secrets masked:

```text
"masterSecret": "<redacted sha256:a41fe8d02f1d>"
"unattended": "<scram-verifier:set>"
"botToken": "<set>"
```

Use `p2pgate master show --reveal` when you really need the value.

## Doctor

```sh
p2pgate doctor
```

New checks:

| Check | Result |
|---|---|
| masterSecret fingerprint | always shown (never the secret) |
| config older than 180 days | warning: consider `p2pgate master reset` |
| each `targets.<name>` on `127.0.0.1` | warning when the port does not answer |
| SOCKS allowlist `0.0.0.0/0` | warning: effectively an open proxy |
| SOCKS per-client entries | counted |

## Per-client SOCKS allowlist

```json
"socks": {
  "enabled": true,
  "allow": ["192.168.1.0/24:8080"],
  "perClient": {
    "<clientPublicKeyHex>": ["10.0.0.0/8:443"]
  }
}
```

- the per-client list **replaces** the global list for that key (not a union)
- keys without an entry fall back to `allow`
- invalid keys or empty lists fail config validation

## UX

- pressing Enter on an empty credential prompt now re-prompts silently instead
  of printing a validation error

## Compatibility

- drop-in replacement for v1.8.4
- existing configs keep working; `perClient` is optional
- no protocol change

## Tests

`npm test` → 50 checks (2 new):

- config redaction hides secret material
- SOCKS per-client allowlist overrides the global list
