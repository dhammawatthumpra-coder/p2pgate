# p2pgate v1.7.0

Small feature release: override the Server target port from the command line.

## Added

```sh
p2pgate server --port 2222
p2pgate server --target-port 2222      # explicit alias
```

- Overrides `targetPort` **for this run only**; the config file is not modified.
- Useful for one-off targets (a second `sshd`, a container port, a test service)
  without editing `~/.p2pgate/config.json`.
- Validation: integer `1-65535`; `--port` and `--target-port` are mutually
  exclusive.
- The banner marks the override:

  ```text
  Target: 127.0.0.1:2222 (this run only, not saved)
  ```

- New `PORT_INVALID` error code with its own hint, instead of the generic
  "config invalid" message.

## Not included

`--port` on the Server does **not** change `localPort`. The Server does not open
a local listener; only the Client does (`p2pgate connect --port <localPort>`).

Multi-port targets (`targets: { ssh: 22, web: 443 }`) are planned for v1.8.

## Compatibility

- Drop-in replacement for v1.6.3.
- No config format change, no protocol change, no dependency change.

## Tests

`npm test` → 37 checks (unchanged). Manual verification:

- Server banner shows the overridden port and keeps `targetPort` in the config
  untouched.
- Echo through the tunnel succeeds against the overridden target port.
- `--port 0` and `--port 22 --target-port 23` are rejected with `PORT_INVALID`.
