# p2pgate v1.7.0

Multi-target routing: the Server can expose several local services and the
Client picks one by name. No SSH port-forwarding required.

## Before / after

Before:

```sh
p2pgate connect --port 18022
ssh -p 18022 -L 8080:127.0.0.1:8080 localhost
```

After:

```sh
# shell access (SSH is just one target)
p2pgate connect --target ssh --port 18022
ssh -p 18022 localhost

# web service — no SSH and no -L involved
p2pgate connect --target web --port 8080
# then open http://127.0.0.1:8080
```

## Server config

```json
{
  "targets": {
    "ssh": { "host": "127.0.0.1", "port": 2222 },
    "web": { "host": "127.0.0.1", "port": 8080 },
    "db":  { "host": "127.0.0.1", "port": 5432, "allow": ["<clientKeyHex>"] }
  },
  "defaultTarget": "ssh"
}
```

- `host` must be `127.0.0.1` (p2pgate never forwards to a remote host)
- `allow` is optional; `"*"` allows any authenticated client
- a config without `targets` keeps the old single-port behaviour

## Client

```sh
p2pgate connect --target web            # saved to client.json
p2pgate client  --target web            # one run only
```

Logs after authentication:

```text
TARGET web -> 127.0.0.1:8080
TUNNEL established slot=... serverKey=... target=web
```

## Compatible

| Combination | Result |
|---|---|
| v1.7 client + v1.7 server | target routing |
| v1.6 client + v1.7 server | uses `defaultTarget` |
| v1.7 client + v1.6 server | connects to the single target; the extra field is ignored |

No config migration is needed.

## Behaviour notes

- `--port` on the Server still overrides the **default target** for that run.
- `--port` on the Client is the local listener; it is independent of targets.
- Unknown or forbidden targets return `TARGET_UNKNOWN` / `TARGET_FORBIDDEN`
  and are not counted as failed authentication attempts.
- `status --json` now reports `targets` and `defaultTarget`.

## Tests

`npm test` → 41 checks (4 new):

- multi-target routing reaches the selected service
- unknown target is rejected without touching the default target
- per-target allowlist rejects a client key
- a client without a target still uses the default target
