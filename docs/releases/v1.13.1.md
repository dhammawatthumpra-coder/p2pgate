# p2pgate v1.13.1

`--socks5` now uses multiplexing by default. Nothing to type, nothing to migrate.

## Why

A single web page opens 20–40 connections. Without mux each one pays a full
HyperDHT lookup (~2 s on a real link); with mux the first connection pays it and the
rest open in ~100 ms. Since 1.13.0 this also works for trusted devices, so the
default helps the common case instead of only power users.

Two 4-hour soaks back this up:

| run | mode | result |
|---|---|---|
| 1.12.1 | password, SOCKS-less target | 79/79 ok, 1 carrier, RSS flat |
| 1.13.0 | trusted device (fast path) | 80/80 ok, 1 carrier, `fastpath=1`, RSS decreasing |

Details in [`docs/SOAK.md`](../../docs/SOAK.md) §1.5–1.6.

## What changed

```sh
p2pgate connect -s <secret> -p <password> --socks5 1080   # mux is on
p2pgate connect -s <secret> -p <password> --socks5 1080 --no-mux   # turn it off
```

| mode | mux default |
|---|---|
| `--socks5` gateway | **on** |
| plain tunnel / `--target` / SSH | off (unchanged, opt in with `--mux`) |

- `--no-mux` wins over `--mux` and over the config.
- `"mux": false` in `client.json` disables the SOCKS default for that machine.
- server config is unchanged (`mux`, `muxPeekMs` gate the fast-path upgrade).

## Fixed

`readExactly()` in the self-test harness discarded bytes beyond the requested length.
With mux the SOCKS reply (10 B) and the target banner (20 B) often arrive in one
segment, so the banner was thrown away and the test timed out. The harness now keeps
surplus bytes per socket and serves them to the next read. Product code was not
affected — this only made the new default untestable until it was fixed.

## Tests

`npm test` → **72 checks** (one new: mux defaults on for socks5, off for plain
tunnels, `--no-mux` wins).

## Compatibility

No protocol change. `--mux` clients on 1.12 servers behave as before. Defaulting mux
on for SOCKS only changes which client path is chosen, and `--no-mux` restores the
old behaviour exactly.
