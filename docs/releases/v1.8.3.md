# p2pgate v1.8.3

Adds first-class `masterSecret` management. Before this release the only way to
rotate it was to edit `config.json` by hand.

## New commands

```sh
p2pgate master show              # fingerprint only (safe to paste in a ticket)
p2pgate master show --reveal     # full value
p2pgate master reset --yes       # rotate + timestamped backup
p2pgate master reset --dry-run   # show what would change, write nothing
p2pgate master reset --yes --json
```

## What `master reset` does

1. reads the current config and validates it
2. writes `config.json.bak-<timestamp>` next to it (mode `0600`)
3. generates 32 random bytes (64 hex) and saves through the normal normaliser
4. prints the new value, the backup path, and the next steps
5. records `master.reset` in the audit log (fingerprints only — never the secret)

Server and client configs are both supported:

| Mode | After rotating |
|---|---|
| `server` | restart `p2pgate server`; the DHT identity changes |
| `client` | the next connection uses the new value; no restart |

## What is not affected

- the connection password (`p2pgate password reset` is separate)
- trusted devices / registered client keys
- targets and SOCKS allowlists

## Warnings

- every Client must run `p2pgate connect -s <new value>`; otherwise they get
  `PEER_NOT_FOUND`
- the old value stops working immediately for new connections
- remove the old value from shell history and notes
- `--yes` is required in a non-interactive shell
