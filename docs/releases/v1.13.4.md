# p2pgate v1.13.4

Test and documentation release. No runtime changes.

## Fast-path matrix

Both 1.13.x regressions lived on the fast path — the route a trusted device (your own
machine) actually uses — so every user-selectable combination now has an explicit
check. Six new cases, **82 checks** total:

| case | what it locks down |
|---|---|
| mux + `--target` + 1 MiB | target routing and a large transfer on one carrier |
| no-mux + `--target` + eager line | target request and a payload written immediately (SSH style) |
| no-mux + binary inside the peek | arbitrary bytes are forwarded, not parsed |
| mux + parallel channels | two simultaneous connections on one carrier |
| socks + mux default | the combination that exposed the `readExactly` harness bug |
| socks + `--no-mux` | SOCKS on a dedicated stream |
| `mux: false` server + `--target` | target capability is independent of mux |

## Badge cache

The README badge showed `Socket in progress` long after npm finished analysis,
because GitHub/npm cache the SVG. The URL is now
`badge.socket.dev/npm/package/p2pgate?v=1.13.4`, and `docs:check` fails if that query
does not match `package.json` — so each release fetches a fresh image instead of a
frozen one.

## Upgrading

Nothing to change at runtime:

```sh
npm i -g p2pgate@1.13.4
```

`npm test` → **82 checks**.
