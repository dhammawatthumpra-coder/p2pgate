# p2pgate v1.4.0

A lightweight P2P TCP gateway for SSH over HyperDHT, with mutual SCRAM,
verification policy modes, a dual-source device registry, and a local control
plane.

## Highlights

- **Local control plane**
  - `p2pgate status`, `p2pgate pin`, and `p2pgate revoke <key>`
  - POSIX control socket `0600`; Windows named pipe
  - `revoke` closes active tunnels immediately and persists the suspension
- **`p2pgate doctor`**
  - Read-only diagnostics for Node, config, permissions, registry, sshd,
    control plane, lockout state, and client key
  - Thai output with `✅` / `⚠️` / `❌` and exit code 1 on critical failures
- **Safer trusted devices**
  - `--mode trusted` requires `--expires` or explicit `--permanent`
  - warns that trusted devices bypass the PIN prompt
- **Verification modes**
  - `hybrid`, `key-only`, `two-step`
  - fast-path for trusted devices, two-step for `scram` devices
- **Dual-source registry**
  - `config.json` plus `trusted_devices`
  - expiry, labels, POSIX permission checks, and live reload
- **Mutual SCRAM**
  - 10-character Base32 Session PIN
  - SCRAM verifier for the Unattended Password
  - progressive lockout: 3/15m, 6/6h, 10/permanent
  - `p2pgate unlock` restores access without restarting the server

## Install

```sh
npm install -g p2pgate
p2pgate --version
```

Or from source:

```sh
git clone https://github.com/incognitums/p2pgate.git
cd p2pgate
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm link --ignore-scripts
```

## Quick start

On the Server:

```sh
p2pgate setup          # choose Server, mode hybrid
p2pgate devices list
p2pgate server
```

On the Client:

```sh
p2pgate setup          # choose Client, same masterSecret
p2pgate client
ssh -p 8022 localhost
```

## Tested

- Windows 11 (Node 24)
- Termux / Android 15 (Node 24, aarch64)
- LAN and 4G/mobile network
- Real SSH through the tunnel to Termux sshd
- Control plane: status, pin, revoke, unlock, doctor
- Hybrid mode with Session PIN and fast-path

Long-running, multi-client stress, and additional NAT scenarios are still
being tested.

## Security notes

- The control socket is local-only; the PIN is read from memory and never
  written to disk or logs.
- `trusted` devices bypass the PIN prompt by design; use an expiry.
- `key-only` has no second factor; protect the client key carefully.
- Windows does not enforce POSIX permission/ACL checks.
- `revoke` closes the p2pgate stream; it does not kill an OS-level SSH session.
