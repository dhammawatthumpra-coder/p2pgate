# p2pgate v1.11.0

Two observability features for sysadmins, no new network surface.

## `p2pgate ping`

```sh
p2pgate ping
p2pgate ping --count 5
p2pgate ping --json
```

```text
=== p2pgate ping ===
slot 498557  serverKey 16db1bcb…
   auth 92 ms   rtt min/avg/max 0/1/1 ms   (2 pings)
```

- measures auth time separately from the ping RTT
- tries the current slot then the previous one
- exits `1` when nothing answers
- uses the normal SCRAM handshake; no listener, no port left open

## Traffic counters in `status`

```text
Traffic รวม: in 1.2 KiB / out 8.4 MiB
Stream ที่ใช้งาน: 2
  - ssh (tcp) peer=3d8f1df0… in 512 B out 8.4 MiB
  - dns (udp) peer=3d8f1df0… in 120 B out 240 B
```

- in-memory only; totals survive stream close, reset on restart
- `kind` distinguishes `tcp` and `udp`
- `p2pgate status --json` exposes the same data
- `p2pgate status --watch` refreshes every second (Ctrl+C to stop)

## Why not `pipe`/`cp`?

File writing on the Server would add path handling, overwrite rules, disk
quotas and audit requirements. Kept out of this release on purpose.

## Tests

`npm test` → 54 checks (2 new):

- status reports in-memory traffic counters
- ping measures RTT without opening a listener

Manual: `p2pgate ping --count 2 -p <password>` reported
`auth 92 ms rtt min/avg/max 0/1/1 ms`.

## Compatibility

Additive only: new subcommand and extra `status` fields. No config or protocol
change; old clients ignore the new fields.
