# p2pgate v1.5.0

Auditability, key protection, and automation improvements. The tunnel and
SCRAM protocol remain compatible with v1.4; the local control protocol is now
version 2.

## Highlights

- **JSONL audit log**
  - `~/.p2pgate/audit.log`, mode `0600`
  - auth success/failure/decline, fast-path, control revoke, PIN rotation,
    device add/remove/revoke/unlock
  - rotation to `audit.log.1`
  - never records PINs, passwords, passphrases, seeds, verifiers, or tokens
- **Passphrase-protected client keys**
  - scrypt + AES-256-GCM
  - `p2pgate keygen --passphrase`
  - `p2pgate client --key-passphrase-stdin`
  - `P2PGATE_KEY_PASSPHRASE`
  - plaintext keys remain compatible
- **Machine-readable output**
  - `p2pgate status --json`
  - `p2pgate doctor --json`
- **Hardened control plane**
  - per-server control token at `~/.p2pgate/control.token`
  - POSIX socket owner/permission verification
  - token-based authentication on Windows named pipes
  - protocol version `2`
- **Device visibility**
  - `p2pgate devices list` shows lockout/revocation state and failures

## Install

```sh
npm install -g p2pgate@1.5.0
p2pgate --version
```

Or upgrade:

```sh
npm install -g p2pgate@latest
```

## Upgrade notes

- Update both Server and Client to v1.5 because the control protocol changed.
- The tunnel/auth protocol remains compatible with v1.4.
- Existing plaintext client keys continue to work. To protect an existing key:

  ```sh
  p2pgate keygen --passphrase
  ```

- `auditLog` defaults to enabled. Disable it with:

  ```json
  "auditLog": { "enabled": false }
  ```

## Tested

- Windows and Termux automated self-test
- Real SSH through the tunnel on LAN and 4G
- Control status/pin/revoke/unlock and doctor
- npm install on Termux

Long-running, multi-client stress, and additional NAT scenarios remain pending.
