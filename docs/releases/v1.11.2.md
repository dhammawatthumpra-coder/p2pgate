# p2pgate v1.11.2

Fixes the default config path for client-side commands.

## Symptom

On a client machine (no Server config), client commands failed with:

```text
$ p2pgate ping
❌ Error: configuration file not found: C:\Users\...\.p2pgate\config.json
👉 ยังไม่มีไฟล์ตั้งค่า กรุณารัน: p2pgate setup
```

The same happened to `config validate`, `client`, `udp`, `doctor`, `master`
and `keygen` when run without `--config`.

## Fix

Client-side commands now resolve the config like this:

1. `--config <path>` when given
2. `~/.p2pgate/config.json` when it exists (Server)
3. `~/.p2pgate/client.json` when it exists (Client)
4. otherwise the default Server path, so the error message stays accurate

Server-only commands (`server`, `devices`, `status`, `password`, `revoke`,
`unlock`) still default to `config.json`.

## Ping hint

When the Server is older than 1.11 and does not understand the ping frame, the
client reports:

```text
slot 498558  not found (AUTH_PROTOCOL — server อาจเป็นรุ่นเก่ากว่า 1.11)
```

## Compatibility

No protocol or config change. `npm test` → 54 checks (unchanged).
