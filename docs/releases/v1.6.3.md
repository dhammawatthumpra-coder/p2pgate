# p2pgate v1.6.3

Messaging fix for the lazy credential prompt. No behaviour change.

## Why

`p2pgate client` printed this at startup:

```text
🔐 จะถาม PIN เฉพาะเมื่อเซิร์ฟเวอร์ต้องใช้ two-step (trusted/key-only ไม่ถาม)
```

but the prompt only appears **after** an `ssh` connection arrives, because the
client deliberately waits for the server to ask. That looked like a broken or
missing prompt: the tunnel said "ready" yet nothing happened until `ssh`.

The lazy prompt is intentional — a trusted device must connect without any
input. The wording was the problem, not the behaviour.

## What changed

| Where | Before | After |
|---|---|---|
| Startup hint | `จะถาม PIN เฉพาะเมื่อเซิร์ฟเวอร์ต้องใช้ two-step` | `PIN/รหัสผ่านจะถูกถามเมื่อมี connection เข้ามาและเซิร์ฟเวอร์ร้องขอ (trusted/key-only ไม่ถาม)` |
| `--pin-stdin` hint | `จะอ่าน ... เฉพาะเมื่อเซิร์ฟเวอร์ต้องใช้ two-step` | `จะอ่าน ... เมื่อเซิร์ฟเวอร์ร้องขอ (ไม่ถามตอนเริ่ม)` |
| Before prompt | (nothing) | `เซิร์ฟเวอร์ขอการยืนยันตัวตน: กรอก PIN (10 ตัว) หรือรหัสผ่าน (12 ตัวขึ้นไป)` |

Now the sequence is understandable:

```text
✅ อุโมงค์พร้อมใช้งานแล้ว
   เปิดพอร์ตเฉพาะ: 127.0.0.1:8022
กด Ctrl+C เพื่อหยุดอย่างปลอดภัย
[03:26:34.120Z] เซิร์ฟเวอร์ขอการยืนยันตัวตน: กรอก PIN (10 ตัว) หรือรหัสผ่าน (12 ตัวขึ้นไป)
🔐 PIN (10 ตัว) หรือรหัสผ่าน (12 ตัวขึ้นไป):
```

## Compatibility

Drop-in replacement for v1.6.2. No config, protocol or dependency change.
