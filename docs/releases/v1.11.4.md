# p2pgate v1.11.4

Ops conveniences: host aliases, an audit viewer, and a server that can stop
itself. No protocol change, no new dependency.

## Host aliases

```sh
p2pgate connect -s <secret> -p <password> --save home-pi
p2pgate connect @home-pi
p2pgate ping @home-pi
p2pgate ping --all
p2pgate hosts list
p2pgate hosts remove home-pi
```

- stored in `~/.p2pgate/hosts.json` with mode `0600`
- the file contains `masterSecret` values — treat it like `client.json`
- `ping --all` measures one handshake per host and prints a compact table
  (`@name  ok  connect Nms  auth Nms` or the error code)
- `--all` uses the same password/credential source for every host; trusted
  (fast-path) hosts need no password at all

## Audit viewer

```sh
p2pgate audit --tail 20
p2pgate audit --failures
p2pgate audit --since 24h
p2pgate audit --json
```

- reads the tail of `audit.log` (default 256 KiB window) instead of the whole file
- `--failures` keeps `auth.failure`, `auth.declined`, `control.revoke`,
  `locked` and `timeout` events
- output: `time  event  key(8)  target/mode/reason`
- never prints secrets — the audit writer already strips them

## Self-stopping server

```sh
p2pgate server --ttl 30m     # shut down 30 minutes after start
p2pgate server --idle 15m    # shut down after 15 minutes without connections
p2pgate server --once        # shut down after the first session ends
```

- timers live in memory only
- on shutdown the server stops accepting connections and waits up to 60 s for
  active sessions before closing them
- useful for temporary tunnels (`--port 8080`) that you might forget to close

## Tests

`npm test` → 57 checks (3 new):

- hosts.json stores and removes aliases
- audit viewer filters by failure and tail limit
- server `--ttl` closes itself and removes the control socket

## Compatibility

Additive only. Existing commands are unchanged; `hosts.json` is optional.
