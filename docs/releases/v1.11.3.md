# p2pgate v1.11.3

Fixes `p2pgate ping` for trusted (fast-path) clients.

## Symptom

With a trusted device the command reported:

```text
slot 498558  not found (AUTH_PROTOCOL — server อาจเป็นรุ่นเก่ากว่า 1.11)
```

even though the Server was already on 1.11.

## Cause

`ping` sent an extra `ping` frame after the SCRAM handshake. A trusted device
takes the **fast-path**: the Server answers `FASTPATH_READY` and immediately
pipes the stream to the target without reading a proof. The ping frame was
therefore forwarded to sshd, and the reply was not a ping frame → `AUTH_PROTOCOL`.

## Fix

`ping` now measures the **authenticated handshake** instead of an extra frame:

```text
slot 498558  serverKey 1f0ea5c2…
   connect 170/1092/2013 ms   auth 24/31/38 ms   (2 attempts)
```

- `connect` = time to open the DHT stream
- `auth` = SCRAM round trip (or the instant fast-path acknowledgement)
- `--count N` repeats the handshake N times and reports min/avg/max
- works in `fastpath`, `key-only`, and challenge modes
- still opens no listener and leaves no port behind

The server-side ping frame handler was removed (no longer needed), which also
removes an unused protocol branch.

## Compatibility

- no config change
- a v1.11.2 client can still talk to a v1.11.3 server and vice versa for normal
  tunnels; only the `ping` subcommand changed

## Tests

`npm test` → 54 checks; the ping check now asserts one handshake sample per
`--count` and `SELF-TEST PASSED` on Termux.
