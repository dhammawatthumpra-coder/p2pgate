# p2pgate v1.8.4

Small follow-up to v1.8.3 for incident response.

## Added

```sh
p2pgate master reset --yes --no-backup
```

- rotates the masterSecret without writing `config.json.bak-<timestamp>`
- useful when the old secret leaked: keeping a backup of it on disk serves no
  purpose and complicates cleanup
- the command prints a warning that the previous value is gone from disk

## Documentation

`SECURITY.md` now has an **Incident response** section with the correct order of
operations:

```sh
p2pgate revoke <clientKey>          # stop the bleeding first
p2pgate password reset
p2pgate master reset --yes --no-backup
# restart the server, then update every client with connect -s
rm -f ~/.p2pgate/quickstart.txt
rm -f ~/.p2pgate/config.json.bak-*
```

It also states clearly what each step does and does not change:

| Action | Changes | Does not change |
|---|---|---|
| `revoke` | that key's access, live sessions | identity, password |
| `password reset` | the SCRAM verifier | identity, keys |
| `master reset` | DHT identity | password, keys, targets |
| `master show` | nothing | — |
