# p2pgate v1.6.0

Zero-setup server, password-based access, and one-line client connect.

## Highlights

- **`p2pgate server` works without setup**
  - first run creates the config
  - generates `masterSecret` and a connection password
  - stores only a SCRAM verifier
  - starts immediately
- **`p2pgate connect`**
  - no client-side setup
  - generates the client key automatically
  - prompts for `masterSecret` + password
  - one-line form:

    ```sh
    p2pgate connect -s <masterSecret> -p <password>
    ```

- **`authMode`**
  - `password` (default for zero-setup): unknown client keys may authenticate
    with the connection password
  - `registry`: existing key-whitelist model, used by advanced `setup`
- **`p2pgate password reset`**
- **`P2PGATE_LANG=en|th` / `--lang`** for setup, quickstart, server, connect,
  and help
- Advanced `p2pgate setup` remains available

## Install

```sh
npm install -g p2pgate@1.6.0
p2pgate --version
```

## First run

Server:

```sh
p2pgate server
```

Client:

```sh
p2pgate connect
# or:
p2pgate connect -s <masterSecret> -p <password>
ssh -p 8022 localhost
```

## Upgrade notes

- Existing configs are not switched to password mode automatically.
- A config without `authMode` and with non-empty `allowedClientKeys` remains
  `registry`.
- The tunnel/auth protocol remains compatible with v1.5.
- Register a client key with `p2pgate devices add` if you want fast-path or a
  key whitelist.

## Security

- The generated password is 24 Base32 characters.
- `masterSecret` and the password are secrets; do not commit them.
- `-p` on the command line may be visible in shell history/process lists.
  Prefer the hidden prompt, `--password-stdin`, or `P2PGATE_PASSWORD`.
- Headless first-run credentials are written to `~/.p2pgate/quickstart.txt`
  (mode `0600`); delete the file after copying the values.
