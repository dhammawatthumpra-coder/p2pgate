# p2pgate v1.10.0

UDP forwarding, opt-in and scoped: datagrams travel inside the existing
authenticated tunnel.

## Why framing

`hyperdht` 6.36 exposes streams only, so UDP is carried as:

```text
[length: uint16][payload]
```

Maximum datagram is **1200 bytes**; larger ones are dropped and logged rather
than fragmented.

## Server config

```json
"udpTargets": {
  "dns": { "host": "127.0.0.1", "port": 53 },
  "ntp": { "host": "127.0.0.1", "port": 123 }
}
```

## Client

```sh
p2pgate udp --target dns --listen 5353
```

Optional defaults in `client.json`: `"udpTarget": "dns"`, `"udpListen": 5353`.

Placeholder credentials are requested lazily: a trusted/fast-path device never
sees a prompt; otherwise `-p`, `--password-stdin`, `P2PGATE_PASSWORD` or the
hidden prompt are used.

## Sessions

| Event | Behaviour |
|---|---|
| first datagram from `ip:port` | opens one tunnel stream and authenticates |
| reply | framed back to the same endpoint |
| idle 60 s | session closed |
| stream error | session removed; next datagram re-opens |

## Security

- the client sends a **target name**, never `host:port`
- `udpTargets.*.host` must be `127.0.0.1`
- replies can only return through the originating stream, so the Server cannot
  be used as a UDP reflector or open resolver
- oversized datagrams are dropped on both sides

## Logs

```text
server: UDP SESSION client=<key> target=dns -> 127.0.0.1:53
server: UDP SESSION closed ... datagrams=12
client: UDP TUNNEL established slot=... target=dns
client: UDP LISTENING on 127.0.0.1:5353 (target dns)
```

## Limitations

- IPv4 only
- one stream per client endpoint (no multiplexing yet)
- no ordering/retransmission — UDP semantics
- not available through SOCKS5

## Compatibility

- opt-in: configs without `udpTargets` behave exactly as v1.9.1
- no protocol version change; `udp` is an optional handshake field

## Tests

`npm test` → 52 checks (2 new):

- UDP datagrams are forwarded through the tunnel
- UDP datagrams above the limit are dropped

Manual: `p2pgate udp --target echo --listen 5354` returned `ECHO:hello-udp`
and the Server logged `UDP SESSION ... target=echo`.
