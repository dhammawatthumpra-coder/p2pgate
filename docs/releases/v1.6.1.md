# p2pgate v1.6.1

Patch release for a race between the password prompt and the auth stream.

## What was wrong

`p2pgate client` / `p2pgate connect` asked for the PIN/password **after** the
DHT stream was already open, and the server waited only a short time for the
client to respond. When a human took a while to type — or the server restarted
while the prompt was open — the stream died first. The client then reported:

```text
authentication failed: ไม่ได้รับข้อความท้าทายจากเซิร์ฟเวอร์
```

The next connection usually succeeded because the credential was already cached,
which made the failure look random.

## What changed

- **Prompt moved after the challenge.** The client now sends `READY`
  immediately, receives the challenge, and only then asks for the password.
  Typing time no longer competes with connection setup.
- **Server waits for the proof inside the pre-auth window** instead of the
  strict auth timeout, because the password is typed after the challenge.
- **One automatic retry** when the stream closes mid-handshake, using the
  already-cached credential.
- **Clearer messages and logs:** `การเชื่อมต่อขาดระหว่างรอการยืนยันตัวตน
  (ลองใหม่ได้)` and `AUTH TIMEOUT ... stage=ready|proof`.
- A proof timeout is no longer counted as a failed authentication attempt, so a
  slow typist cannot trip the lockout counter.

## Upgrade guidance

- **Server and client can be upgraded independently.** A v1.6.1 server is more
  tolerant of slow v1.6.0 clients; a v1.6.1 client benefits from the retry even
  against a v1.6.0 server.
- No config changes, no protocol version change, no new dependency.

## Tests

`npm test` → 37 checks (2 new):

- slow credential entry does not break authentication
- client retries once when the auth stream closes mid-handshake
