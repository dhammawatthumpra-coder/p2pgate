# p2pgate v1.8.2

Patch release that fixes a config save/load round-trip bug.

## Symptom

After a command that re-saves the config (for example `p2pgate connect`,
`p2pgate password reset`, or a wizard run), the next start failed with:

```text
❌ Error: targets.default.allow must be a non-empty array of client keys or "*"
👉 ค่าใน config ไม่ถูกต้อง กรุณาตรวจสอบหรือรัน p2pgate setup ใหม่
```

The file was not corrupted by hand — `saveConfig()` wrote
`"allow": null` and `"socks": { "allow": [] }`, and the loader then rejected
the values it had just produced.

## Fix

- `targets.<name>.allow: null` is accepted and means "no key restriction"
- `socks.allow: []` is accepted while `socks.enabled` is `false`
  (still rejected when SOCKS is enabled without entries)
- client configs no longer persist `targets`, `defaultTarget`, or `socks`;
  the client never used them, and writing them created the failure
- new self-test: a normalized config must survive a save → load round-trip

## If you are on 1.8.1 right now

Either upgrade, or edit `~/.p2pgate/client.json` and delete the whole
`"targets": { ... }` / `"defaultTarget": ...` block. The client does not need
them. Setting `"allow": "*"` also works but leaves unnecessary policy in the
file.

## Compatibility

- drop-in replacement for v1.8.1; no config schema change
- server configs keep `targets`/`socks`; only client configs are trimmed

## Tests
