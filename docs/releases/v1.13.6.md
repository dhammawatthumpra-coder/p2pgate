# p2pgate v1.13.6

Data-integrity fix for fast-path sessions, plus optional stream compression.

## Fixed

**Fast-path (trusted device) dropped payload after the first newline.**

`peekControlLine()` returned only the first line as `raw`, while the bytes after the
newline sat in `leftover`. The no-upgrade fast-path branch forwards `peek.raw` as
payload, so everything after the first newline inside the 200 ms peek window was lost.
Measured on a real link: **65,518 bytes missing from every 64 MiB transfer**.

`raw` now means every byte read, and the self-test covers a payload with data after the
first newline.

Affected 1.13.5 when a trusted device sent its first payload chunk within the peek window
and the chunk contained a newline plus more data (for example an HTTP request head
followed by a body).

## Added

Optional stream compression, **off by default** and opt-in on both ends:

```sh
p2pgate server --compress
p2pgate connect --compress
```

- mux channels and non-mux tunnels (challenge proof and fast-path peek line)
- zstd when the Node build has it (>= 22.15), gzip otherwise
- `compress: "auto"` samples the first 32 KiB / 60 ms (mux only)
- decompression bomb guard: 4 GiB output or 1000x expansion
- measured ~2.4–2.6x server-side on 64 MiB text/log over 4G, ~1.0x on incompressible data

SSH payloads are already encrypted, so compression does not help them; use `ssh -C` for
that case. See [`docs/spikes/compress-mux.md`](../spikes/compress-mux.md) for limits.

## Upgrading

```sh
npm i -g p2pgate@1.13.6
```
