# p2pgate v1.11.1

Fixes a self-test bug that could make `npm test` fail and then hang.

## Symptom

On a machine without `~/.p2pgate/client-key.json` (fresh install, CI runner,
Termux), `npm test` failed with:

```text
Error: client key file not found: /data/data/com.termux/files/home/.p2pgate/client-key.json
    at async startClient (.../src/client.js)
    at async main (.../src/self-test.js)
```

and the process sometimes never exited — the shell command appeared to run for
tens of minutes.

## Cause

1. The UDP test called `startClient()` with the test base config, which did not
   override `clientKeyPath`, so it fell back to the user's real default path.
2. After the failure, a DHT node was still open. `process.exitCode = 1` alone
   does not end the process while handles remain, so `npm test` hung.

## Fix

- the UDP test always uses a temp `clientKeyPath`
- the self-test flushes stdout/stderr and then calls `process.exit(0|1)`, so a
  failure exits immediately instead of waiting on leftovers

Verified on Termux: `timeout 240 node src/self-test.js` now finishes in ~17 s
with `SELF-TEST PASSED`.

## Why it matters

`npm test` is the documented post-install check (and what `prepublishOnly`
runs). A hang there looks like a broken package even though the daemon is fine.

## Compatibility

No runtime change. `npm test` → 54 checks (unchanged).
